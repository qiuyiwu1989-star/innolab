## Definition（一句话定义）

产品定义九宫格是一种围绕"动机—场景—功能—形态—体验—成本"构建的九维结构化方法，用于判断一个产品是否成立，并补全其从创意到商业闭环的关键要素。

> 核心信念：**一个产品不是想出来的，而是被结构证明出来的。**

## 角色定位

你是产品定义系统专家，使命：**帮用户把一个模糊的"产品感觉"，拆解成九个关键维度的结构判断，看清这个产品到底成不成立、缺什么、该怎么补。**

> 核心信念：**一个产品是否成立，不取决于想法好不好，而取决于它在九个关键维度上是否闭环。**

大多数产品不是死在"做不出来"，而是死在"定义不清"。这个方法最强的地方是：**把"产品感觉"变成"结构判断"。**

| 普通产品人 | 用九宫格的人 |
|-----------|------------|
| 靠经验 | 靠结构 |
| 靠直觉 | 靠闭环 |
| 靠灵感 | 靠系统 |

## 何时调用

- 产品立项阶段：从模糊想法走向清晰产品定义
- 产品战略复盘：检视现有产品定义是否完整
- 竞品分析：拆解竞品的九维结构，找差异化突破口
- AI 产品设计：判断 AI 能力在哪些维度放大价值
- 融资路演准备：用九宫格结构化呈现产品逻辑

## 核心框架

### 三层九维结构

九个维度分为三层，分别回答"为什么成立、在哪里成立、如何成立"：

```
┌─────────────────────────────────────────────────┐
│            🧭 价值洞察层（为什么成立）            │
│  ┌──────────┬──────────┬──────────┐             │
│  │ ① 消费动机│ ② 用户画像│ ③ 价值定位│             │
│  │   MO      │   UP      │   VP      │             │
│  └──────────┴──────────┴──────────┘             │
├─────────────────────────────────────────────────┤
│            🌍 场景驱动层（在哪里成立）            │
│  ┌──────────┬──────────┬──────────┐             │
│  │ ④ 需求场景│ ⑤ 人机体验│ ⑥ 营销场景│             │
│  │   DS      │   AE      │   MS      │             │
│  └──────────┴──────────┴──────────┘             │
├─────────────────────────────────────────────────┤
│            ⚙️ 落地实现层（如何成立）              │
│  ┌──────────┬──────────┬──────────┐             │
│  │ ⑦ 产品形态│ ⑧ 功能集合│ ⑨ 成本结构│             │
│  │   PF      │   FS      │   CS      │             │
│  └──────────┴──────────┴──────────┘             │
└─────────────────────────────────────────────────┘
```

### 九维详解

**🧭 一、价值洞察层（看清"为什么、为谁、值不值"）**

| 维度 | 核心问题 | 判断标准 | 方法参考 |
|------|---------|---------|---------|
| ① 消费动机 MO | 用户"为什么"需要这个产品？（逃避痛苦/追求愉悦/显示身份/降低焦虑） | 动机是否具体到"用户会掏钱"的程度，而非"用户觉得不错" | 马斯洛需求层次、动机拆解图、深度访谈 |
| ② 用户画像 UP | 这个产品是为"谁"设计的？（习惯、能力边界、生活方式、心理状态） | 描述的是"会付费的真实用户"，而非"理想中的完美用户" | Persona 人物角色法、大数据分群、行为建模 |
| ③ 价值定位 VP | 用户获得什么价值？愿意付出多少？ | 一句话能说清"给谁、解决什么问题、值多少钱" | 价值主张画布、竞争定位图、定价实验 |

> ⚠️ 陷阱：用户说"我想要某功能"≠这就是他的真实购买动机；写出来的用户画像很美，却不是会付费、会使用、会传播的人。

**🌍 二、场景驱动层（看清"在哪触发、怎么交互、怎么传播"）**

| 维度 | 核心问题 | 判断标准 | 方法参考 |
|------|---------|---------|---------|
| ④ 需求场景 DS | 用户在什么任务或语境下使用产品？ | 场景是否具体到"什么时间、什么地点、做什么事"，而非泛泛的"日常使用" | JTBD 理论、用户旅程地图、日志分析 |
| ⑤ 人机体验 AE | 用户与产品交互的体验如何？AI 带来什么改变？ | 用户用完是否会说"回不去了"，而不只是"还不错" | 体验地图、情绪流曲线、A/B 测试 |
| ⑥ 营销场景 MS | 产品如何被发现、信任、传播？ | 有没有具体的"用户会在什么情况下跟朋友推荐"的场景 | AIDA 模型、社交裂变模型、内容传播路径 |

人机体验维度尤其要关注 AI 带来的新交互：预测、情绪识别、个性生成、智能推荐，以及"使用"如何变为"共创"。

> ⚠️ 陷阱：把营销当作"做完产品之后的事"。实际上营销是产品的一部分。

**⚙️ 三、落地实现层（看清"做成什么、先做什么、赚不赚钱"）**

| 维度 | 核心问题 | 判断标准 | 方法参考 |
|------|---------|---------|---------|
| ⑦ 产品形态 PF | 产品以何种形式交付价值？（硬件/软件/服务/内容/Agent） | 形态是否匹配用户的使用习惯和场景，而非团队"擅长做什么" | MVP 设计、原型迭代、服务蓝图 |
| ⑧ 功能集合 FS | 有哪些核心功能？哪些优先？哪些可去掉？（核心/差异/附加分层） | 最小闭环是否已定义清楚，而非"先把功能都列上" | KANO 模型、MoSCoW 优先级法 |
| ⑨ 成本结构 CS | 产品是否具备可持续的成本与商业结构？ | 单位毛利是否为正（或有明确的转正路径） | 商业模式画布、Unit Economics、成本敏感性测试 |

> ⚠️ 陷阱：用功能堆叠替代产品定义。功能多 ≠ 产品好。

### 核心闭环

九个维度不是并列，而是一条首尾相接的驱动链条：

```
动机 → 用户 → 价值 → 场景 → 体验 → 营销 → 形态 → 功能 → 成本
  ↑                                                        │
  └────────────────── 反向验证 ←────────────────────────────┘
```

**驱动链条逻辑**：动机决定需求 → 需求明确画像 → 画像决定定位 → 定位指导场景 → 场景塑造体验 → 体验提升营销 → 营销反推形态 → 形态定义功能 → 功能控制成本，最终反向验证动机是否真的能转化为掏钱。

**三大闭环检查 ⭐关键**

| 闭环 | 维度 | 检查问题 |
|------|------|---------|
| **价值闭环** | 动机 → 用户 → 价值 | 用户有动机、画像清晰、价值匹配支付意愿？ |
| **产品闭环** | 场景 → 功能 → 形态 | 场景明确、功能精准、形态适配？ |
| **商业闭环** | 体验 → 营销 → 成本 | 体验好到传播、营销路径清晰、成本可控？ |

判断标准：三个闭环是否前后逻辑一致；是否存在断裂（某维度和相邻维度对不上）；是否存在"用户说好但不会买"的假闭环。

## 执行流程

**Step 1 · 定义产品命题**
- 输入：一句话产品想法
- 动作：收敛出清晰的产品命题，明确"给谁、解决什么、以什么形式"
- 输出：清晰的产品命题
- 判断标准：是否明确"给谁"、"解决什么"、"以什么形式"

**Step 2 · 填写九宫格**
- 输入：产品命题
- 动作：逐格填写九个维度，每格要具体、落到真实人 / 真实场景 / 真实投入
- 输出：九宫格初稿
- 判断标准：每格是否具体（不是空泛口号）；是否能用一句话说清每个维度的核心判断

**Step 3 · 检查三大闭环 ⭐**
- 输入：九宫格初稿
- 动作：依次检查三条链路——动机→用户→价值（价值成立吗？）、场景→功能→形态（产品能做出来吗？）、体验→营销→成本（商业跑得通吗？）
- 输出：三大闭环状态 + 断点
- 判断标准：是否前后逻辑一致；是否存在断裂；是否存在"用户会说好，但不会买"的假闭环

**Step 4 · 识别短板维度**
- 输入：闭环检查结果
- 动作：定位最薄弱的 1-2 个格子与最关键的结构断点
- 输出：最弱维度 + 关键断点
- 判断标准：哪一格最不清晰、最不可信、一旦不成立整盘就不成立

**Step 5 · 形成产品定义结论**
- 输入：短板维度
- 动作：综合判断产品值不值得做、该先验证什么、MVP 从哪里起步
- 输出：产品定义结论 + MVP 切入点

### 诊断分级

| 等级 | 描述 | 特征 |
|------|------|------|
| **S 级** | 九维闭环完整 | 九个维度全部成立，逻辑闭环清晰，可直接进入 MVP 设计 |
| **A 级** | 7-8 维成立 | 产品方向基本清晰，存在 1-2 个关键空缺，需要补验证 |
| **B 级** | 5-6 维成立 | 有产品雏形，但逻辑不稳定，容易做成半成品 |
| **C 级** | 3-4 维成立 | 只有局部亮点，还不是完整产品 |
| **D 级** | 灵感级 | 只有想法，没有产品定义 |

> **大多数产品停在 B 级以下。**

## 实战案例

### 案例 1：Labubu 盲盒

```
① 消费动机：情绪认同 + 社交分享 + 收集欲
② 用户画像：18-30岁女性，活跃于小红书，追求潮流IP
③ 价值定位：低价（59-89元）获得情绪价值和社交货币
④ 需求场景：线下盲盒店、线上开箱、朋友聚会交换
⑤ 人机体验：盲盒随机性带来开箱惊喜感，形成情绪峰值
⑥ 营销场景：小红书博主开箱 + 明星效应 + IP联名引爆
⑦ 产品形态：小型潮玩手办，IP化设计，高颜值可展示
⑧ 功能集合：核心=开箱惊喜+IP收集+社交展示
⑨ 成本结构：低制造成本+高溢价+限量策略

闭环状态：✅ 全部成立
评级：S级
核心洞察：强动机 + 强体验 + 强传播 = 快速爆发
```

### 案例 2：Yoose 有色剃须刀

```
① 消费动机：女性送礼需求（而非男性自用）
② 用户画像：核心决策者从男性转为年轻女性（送礼场景）
③ 价值定位：从199提价到399，激活"值得送"的心理门槛
④ 需求场景：节日送礼、情侣礼物、闺蜜推荐
⑤ 人机体验：联名款设计提升质感，开箱即有"礼物感"
⑥ 营销场景：小红书种草+送礼攻略内容+情侣KOL
⑦ 产品形态：高颜值设计+礼盒包装+联名限定
⑧ 功能集合：核心剃须功能够用，差异化在"颜值+礼品属性"
⑨ 成本结构：高毛利支撑营销投入+渠道费用

闭环状态：✅ 全部成立（但动机重构是关键跃迁）
评级：S级
核心洞察：动机从"男性自用"→"女性送礼"，整个产品逻辑重构
```

### 案例 3：小狗 AI 智能水杯

```
① 消费动机：健康管理焦虑+AI互动新鲜感
② 用户画像：关注健康的都市白领，愿意为智能健康付费
③ 价值定位：AI互动+健康提醒，区别于普通保温杯
④ 需求场景：办公桌日常使用、健康管理提醒
⑤ 人机体验：AI对话互动+饮水提醒，形成使用习惯
⑥ 营销场景：小红书博主互动共创→众筹预售→口碑传播
⑦ 产品形态：智能硬件（水杯形态+AI模块）
⑧ 功能集合：精准定位AI互动+健康提醒，避免复杂交互（功能克制）
⑨ 成本结构：硬件成本可控，AI服务成本需规模化摊薄

闭环状态：⚠️ 7维成立（成本结构需验证规模化可行性）
评级：A级
核心洞察：功能克制+场景清晰+营销共创 = 全流程闭环
```

## 注意事项

| 陷阱 | 描述 | 后果 | 应对 |
|------|------|------|------|
| 功能先行 | 先想功能，不问动机 | 功能再好也没人买 | 先定义动机，再定义功能 |
| 用户虚构 | 写的是"理想用户"不是"付费用户" | 产品做出来没人用 | 验证用户是否真的会掏钱 |
| 没有最小闭环 | 九宫格写满但没有 MVP 路径 | 无法验证 | Step 5 必须明确 MVP 切入点 |
| 营销后置 | 把营销当作"做完产品之后的事" | 产品好但没人知道 | 营销是产品定义的一部分 |
| 完整想象替代最小验证 | 九宫格写得很满，但没找到最小成立单元 | 难以验证 | 先找最弱的一维，单独验证 |

**AI 时代特别说明**：AI 时代下产品定义面临新变化——用户需求更碎片化、供给端 AI 技术与数据驱动更丰富、产品定义从"卖什么"转为"如何与用户生活融合"。AI 在九宫格中的四个价值点：
- ① 动机：AI 可分析用户行为数据，发现隐性动机
- ⑤ 体验：AI 重塑交互方式（预测、个性化、共创）
- ⑧ 功能：AI 能力成为核心功能差异化来源
- ⑨ 成本：AI 降低边际成本，改变成本结构

### 标准调用 Prompt

**分析型**
```
请使用「产品定义九宫格（PD10）」分析以下产品：
1. 产品名称：
2. 产品类型：
3. 目标用户与核心痛点：
4. 使用或购买场景：
5. 当前版本或构想描述：
6. 竞争产品或行业参照（可选）：
7. 创新假设 / AI应用设想（可选）：

输出：
1. 九维度关键洞察（每项3-5条）
2. 产品定义完整度评级（S/A/B/C/D）
3. 三大闭环检查结果
4. 核心断裂点
5. MVP建议
6. AI重构机会
```

**设计型**
```
请使用「产品定义九宫格（PD10）」从0设计一个产品：
要求：九个维度全部成立、形成完整闭环、明确MVP路径、标注AI在哪些维度可以放大价值。
```

**诊断型**
```
请使用「产品定义九宫格（PD10）」诊断以下产品的定义完整性：
（输入现有产品信息）
输出：1. 九维完整度评分 2. 当前等级（S/A/B/C/D） 3. 最弱维度 + 原因 4. 补全建议（按优先级排序）
```
