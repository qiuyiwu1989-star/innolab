# CG14 · 技能方法卡结构化设计
- 领域：认知 | 动作：设计 | 来源：original
- 首次发表：InnoLab v3.3

## Definition（一句话定义）
一套用于将"模糊方法论"转化为"可调用 Skill"的结构化设计与评估系统。

## 角色定位
你是方法论的"接口设计师"与质检官，使命：**把一个只有定义、没有接口的"半成品方法"，重构成可判断、可执行、可复用的标准方法卡——让任何人拿到就能用、用对场景、用出深度，并能接入更大的方法系统。**

> 核心信念：**"一个方法是否高级，不取决于复杂度，而取决于是否可判断、可执行、可复用。方法卡设计，不是写方法，而是让方法可以被调用——这是认知工业化。"**

## 何时调用
- 把一个脑子里/文章里的"模糊方法论"沉淀成能反复调用的 Skill
- 评估一张现有方法卡写得好不好、缺哪些维度、怎么升级到 S 级
- 批量生产方法库时，统一所有方法卡的表达标准与质量门槛
- 发现某个方法"看完不会用、不知道何时用、不知道跟谁配"时，用它来补全接口
- 把团队的隐性经验/最佳实践标准化为可传承的结构化资产

## 解决什么问题

"没有这个方法时，人们通常犯什么错？"

方法很多，但大多数是半成品——只有定义，没有接口。具体表现为四个典型问题：

| 问题 | 表现 | 后果 |
|------|------|------|
| 无法使用 | 只讲"是什么"，没有"怎么用" | 看完不会操作 |
| 无法判断 | 没有判断标准，不知道自己是否适用 | 用错场景 |
| 无法落地 | 没有步骤+判断锚点 | 概念停留在脑中 |
| 无法连接 | 方法是孤岛，不知道跟谁配 | 无法组合成系统 |

> 本质问题：方法没有"接口化"，无法被调用。

## 核心框架：方法卡 7 维协议

一个方法卡的质量，取决于 7 个维度是否到位。

| 维度 | 本质作用 | 缺失时的表现 |
|------|---------|-------------|
| ① 问题定义 | 判断是否需要 | "我不知道这个方法跟我有什么关系" |
| ② 核心框架 | 建立结构记忆 | 纯文字描述，读完记不住 |
| ③ 步骤+判断 | 保证可执行 | "分析一下"——怎么分析？ |
| ④ 诊断分级 | 提供深度 | 只能回答"是不是"，不能回答"多严重" |
| ⑤ 案例 | 建立迁移能力 | 看完框架不知道怎么落地 |
| ⑥ 陷阱 | 防止误用 | "看起来对但实际错了"的错误 |
| ⑦ 方法关系 | 接入系统 | 方法孤立存在，不知道跟谁配 |

> 核心判断：一个方法是否高级，不取决于复杂度，而取决于"是否可判断、可执行、可复用"。

### 四大核心能力（7维背后的底层能力）

| 能力 | 说明 |
|------|------|
| 方法结构化能力 | 把模糊方法变成结构（矩阵/流程/分类） |
| 方法可执行化能力 | 加入判断标准（满足X→A，否则→B） |
| 方法深度增强能力 | 加入诊断分级 + 案例 |
| 方法系统化能力 | 建立方法之间关系（前置/后续/并行） |

### 三重判断（评估逻辑）

判断一张方法卡是否高级，只看三件事——7 维可压缩为 **判断 × 执行 × 迁移**：

| 判断维度 | 核心问题 | 对应 7 维 |
|---------|---------|----------|
| ① 可判断 | 能不能判断"有没有问题 / 多严重" | 问题定义 + 诊断分级 |
| ② 可执行 | 步骤是否有明确决策标准 | 步骤+判断 |
| ③ 可迁移 | 是否有案例 + 结构 | 案例 + 核心框架 + 陷阱 + 方法关系 |

### 质量分级

| 等级 | 标准 |
|------|------|
| ⭐⭐⭐⭐⭐ S | 7 维全部到位，框架可视化，步骤有判断标准，有完整案例 |
| ⭐⭐⭐⭐ A | 5-6 维到位，可能缺案例或缺诊断分级 |
| ⭐⭐⭐ B | 3-4 维，有框架和步骤，但缺陷阱或方法关系 |
| ⭐⭐ C | 1-2 维，只有定义和简单步骤 |
| ⭐ D | 占位文件，几乎为空 |

## 执行流程

写一张方法卡（或评估一张）必走的七步，每步对应 7 维中的一维：

**Step 1｜问题对齐**
- 输入：一个待结构化的方法 + 它声称解决的事
- 动作：逼问"没有这个方法时，人们具体犯什么错？"
- 输出：一句具体的"问题定义"（让用户判断自己是否需要）

**Step 2｜结构提炼**
- 输入：方法的核心思想
- 动作：抽象为可视化结构——分类（如三类）/ 矩阵（如2×2）/ 流程（步骤）
- 输出：一个表格/矩阵/流程图（核心框架，必须可视化）

**Step 3｜步骤具体化（必须加判断）**
- 输入：核心框架
- 动作：把每步写成带判断标准的动作——❌"分析一下" → ✅"若满足X→用A，否则→用B"
- 输出：可执行的步骤序列（每步含决策标准）

**Step 4｜建立分级体系（关键跃迁点）**
- 输入：步骤产出的结果
- 动作：判断"这个方法能不能分'程度'"，设计分级/分层/分档
- 输出：诊断分级表（让方法能回答"多严重"而非只回答"是不是"）

**Step 5｜补案例（强制）**
- 输入：完整框架 + 步骤
- 动作：走通至少一个完整案例——从输入到每步怎么走到输出
- 输出：一个可迁移的实战案例

**Step 6｜补陷阱（经验沉淀）**
- 输入：使用该方法的真实经验
- 动作：提炼 2-3 个"看起来对但实际错了"的误用
- 输出：注意事项清单

**Step 7｜接入系统（方法关系）**
- 输入：方法库中的其他方法
- 动作：标定前置 / 后续 / 并行关系
- 输出：方法关系，让这张卡不再是孤岛

## 输出格式

这个 Skill 的输出一定是以下两者之一：① 一张按 7 维协议生成的"可用方法卡"；② 一份"方法卡评估报告"（当前等级 + 缺失维度 + 升级路径）。

**方法卡标准结构**：

```
# 中文名（English Name）

## Meta
- ID / Engine / Layer / Type / Origin / Source / 一句话定义

---

## 1. 解决什么问题
"没有这个方法时，人们通常犯什么错" → 让用户判断自己是否需要

## 2. 核心框架
对照表 / 矩阵 / 分类体系 / 流程图 → 必须可视化

## 3. 怎么用
每步：输入什么 → 做什么判断（带判断标准）→ 输出什么

## 4. 诊断分级
怎么判断结果的"程度"——分级/分层/分档

## 5. 案例
一个完整案例：输入 → 每步怎么走 → 输出

## 6. 常见陷阱
2-3个"看起来对但实际错了"的用法

## 7. 方法关系
- 前置：用这个之前最好先做什么
- 后续：用完这个之后通常接什么
- 并行：可以同时用的

## 8. 深度理解 [可选]
高阶用法、哲学洞察、反直觉理解
```

**通用生成 Prompt**：
```
请使用「技能方法卡结构化设计」将以下方法转化为标准方法卡：

【输入方法】（方法名称 + 简单描述）

请输出：
1. 解决什么问题（具体错误场景）
2. 核心框架（必须结构化表达）
3. 使用步骤（每步带判断标准）
4. 诊断分级（至少3级）
5. 一个完整案例（从输入到输出）
6. 常见陷阱（2-3个）
7. 方法关系（前置 / 后续 / 并行）
```

**评估 Prompt**：
```
请使用「技能方法卡结构化设计」评估以下方法卡质量：

【输入】（方法卡内容）

输出：
1. 当前等级（S / A / B / C / D）
2. 缺失的维度
3. 最关键的提升点
4. 如何从当前等级升级到S级
```

## 实战案例

**案例（示例）：把一张 C 级"占位卡"升级到 S 级**

**输入（一张单薄方法卡）**：
> 「五问法」——遇到问题连续问五个"为什么"，找到根本原因。

对照 7 维诊断：只命中了①问题定义的影子，缺核心框架结构、缺步骤判断、缺分级、缺案例、缺陷阱、缺方法关系——**当前 C 级**（只有定义和简单步骤）。

**用本方法逐步升级**：

| 维度 | 升级动作 | 升级后内容（节选） |
|------|---------|------------------|
| ② 核心框架 | 把"问五次"可视化为因果链 | `表象问题 →为什么1→ ... →为什么5→ 根本原因` 的链式结构图 |
| ③ 步骤+判断 | 给每问加判断标准 | "若答案仍是'现象'而非'机制'，继续追问；若已触及制度/动机层，停" |
| ④ 诊断分级 | 加深度分档 | S：追到机制/制度层；A：追到流程层；B：停在表面现象层 |
| ⑤ 案例 | 补一个完整走通的例子 | 设备停机 →为什么1 保险丝断→…→根因 采购未按规格 |
| ⑥ 陷阱 | 补常见误用 | "把'人不小心'当终点"（其实是系统问题）；"硬凑满五问" |
| ⑦ 方法关系 | 接入系统 | 前置：现象观察；后续：对策设计 |

**输出**：一张同时满足"可判断 × 可执行 × 可迁移"的 S 级方法卡。

**关键启示**：升级的本质不是"写更多字"，而是**补齐缺失的接口维度**——尤其是把"问五次"这种模糊动作，变成"每步带判断标准的可执行步骤"+"可分档的诊断分级"，这正是从 C 到 S 的两个关键跃迁点。

## 注意事项

1. **"定义充足但判断缺失"**：写了大量"是什么"，但没有"怎么判断是/不是/多严重"——这是最常见的伪高级。
2. **"步骤模糊"**：用"分析一下""考虑XX"作为步骤，缺少具体判断标准（满足X→A，否则→B）。
3. **"框架只用文字"**：核心框架是纯文字叙述，没有表格/矩阵/流程图，读完记不住、建立不了结构记忆。
4. **AI时代视角**：AI 能在几秒内把任何方法"写得看起来很完整"，但极易停在"定义充足、判断缺失"的 C 级幻觉里——填满了文字，却没有真正的判断锚点和可执行步骤。用本方法做"质检"恰恰是 AI 时代最该坚持的人类把关：让 AI 起草七维内容，但由人逐维校验"是否真的可判断、可执行、可迁移"。这就是把方法卡设计当成"认知工业化"的质量门槛。

## 与其他方法的配合

- **前置**：认知组装者（先会拆解问题、识别方法的可结构化部分，再设计方法卡）。
- **后续**：创造力的十段评估体系（方法卡设计完成后，评估使用者在该方法上的段位）。
- **并行**：所有 Skill（本方法是"母工具"——所有方法卡都必须经过它的结构化标准重写）。
- 说明：上述为方法名引用，具体 ID 以方法库为准。

**本方法在系统中的位置**——它是"母工具"，不是用来做事，而是用来定义怎么做事：

| 角色 | 说明 |
|------|------|
| 认知组装者 → 本方法 | 认知组装者用于拆解方法，本方法把拆解结果结构化为方法卡 |
| 本方法 → 十段评估 | 方法卡设计完成后，十段评估使用者在该方法上的段位 |
| 本方法 ↔ 所有 Skill | 所有 Skill 都必须经过本方法的结构化标准 |

> 它做的是"认知工业化"——统一认知表达标准，让方法可以被批量生产、质量可控、系统化调用。
