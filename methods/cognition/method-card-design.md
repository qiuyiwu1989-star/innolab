# CG14 · 技能方法卡结构化设计
- 领域：认知 | 动作：设计 | 来源：original
- 首次发表：InnoLab v3.3

## 一句话定义
一套用于将"模糊方法论"转化为"可调用 Skill"的结构化设计与评估系统。

## 解决什么问题

"没有这个方法时，人们通常犯什么错？"

方法很多，但大多数是半成品——只有定义，没有接口。具体表现为四个典型问题：

| 问题 | 表现 | 后果 |
|------|------|------|
| 无法使用 | 只讲"是什么"，没有"怎么用" | 看完不会操作 |
| 无法判断 | 没有判断标准，不知道自己是否适用 | 用错场景 |
| 无法落地 | 没有步骤+判断锚点 | 概念停留在脑中 |
| 无法连接 | 方法是孤岛，不知道跟谁配 | 无法组合成系统 |

> 本质问题：方法没有"接口化"，无法被调用。

---

## 核心框架：方法卡 7 维协议

一个方法卡的质量，取决于 7 个维度是否到位。

| 维度 | 本质作用 | 缺失时的表现 |
|------|---------|-------------|
| ① 问题定义 | 判断是否需要 | "我不知道这个方法跟我有什么关系" |
| ② 核心框架 | 建立结构记忆 | 纯文字描述，读完记不住 |
| ③ 步骤+判断 | 保证可执行 | "分析一下"——怎么分析？ |
| ④ 诊断分级 | 提供深度 | 只能回答"是不是"，不能回答"多严重" |
| ⑤ 案例 | 建立迁移能力 | 看完框架不知道怎么落地 |
| ⑥ 陷阱 | 防止误用 | "看起来对但实际错了"的错误 |
| ⑦ 方法关系 | 接入系统 | 方法孤立存在，不知道跟谁配 |

> 核心判断：一个方法是否高级，不取决于复杂度，而取决于"是否可判断、可执行、可复用"。

## 方法卡标准结构

```
# 中文名（English Name）

## Meta
- ID / Engine / Layer / Type / Origin / Source / 一句话定义

---

## 1. 解决什么问题
"没有这个方法时，人们通常犯什么错" → 让用户判断自己是否需要

## 2. 核心框架
对照表 / 矩阵 / 分类体系 / 流程图 → 必须可视化

## 3. 怎么用
每步：输入什么 → 做什么判断（带判断标准）→ 输出什么

## 4. 诊断分级
怎么判断结果的"程度"——分级/分层/分档

## 5. 案例
一个完整案例：输入 → 每步怎么走 → 输出

## 6. 常见陷阱
2-3个"看起来对但实际错了"的用法

## 7. 方法关系
- 前置：用这个之前最好先做什么
- 后续：用完这个之后通常接什么
- 并行：可以同时用的

## 8. 深度理解 [可选]
高阶用法、哲学洞察、反直觉理解
```

## 怎么用

### 标准操作流程（写 Skill 必走）

**Step 1：问题对齐**
这个方法解决的是"什么具体错误"？

**Step 2：结构提炼**
是否能抽象为：
- 分类（如三类）
- 矩阵（如2×2）
- 流程（步骤）

**Step 3：步骤具体化（必须加判断）**
- ❌ 错误：分析一下
- ✅ 正确：如果满足X → 用A，否则 → 用B

**Step 4：建立分级体系（关键跃迁点）**
这个方法能不能判断"程度"？

**Step 5：补案例（强制）**
至少1个完整走通案例

**Step 6：补陷阱（经验沉淀）**
2-3个常见误用

**Step 7：接入系统（方法关系）**
前置 / 后续 / 并行

### 通用生成 Prompt

```
请使用「技能方法卡结构化设计（CG14）」将以下方法转化为标准方法卡：

【输入方法】
（方法名称 + 简单描述）

请输出：
1. 解决什么问题（具体错误场景）
2. 核心框架（必须结构化表达）
3. 使用步骤（每步带判断标准）
4. 诊断分级（至少3级）
5. 一个完整案例（从输入到输出）
6. 常见陷阱（2-3个）
7. 方法关系（前置 / 后续 / 并行）
```

### 评估 Prompt

```
请使用「技能方法卡结构化设计（CG14）」评估以下方法卡质量：

【输入】
（方法卡内容）

输出：
1. 当前等级（S / A / B / C / D）
2. 缺失的维度
3. 最关键的提升点
4. 如何从当前等级升级到S级
```

## 四大核心能力

| 能力 | 说明 |
|------|------|
| 方法结构化能力 | 把模糊方法变成结构（矩阵/流程/分类） |
| 方法可执行化能力 | 加入判断标准（满足X→A，否则→B） |
| 方法深度增强能力 | 加入诊断分级 + 案例 |
| 方法系统化能力 | 建立方法之间关系（前置/后续/并行） |

---

## 评估标准：怎么判断一个方法卡写得好不好

### 三重判断（核心评估逻辑）

判断一个方法卡是否高级，只看三件事：

| 判断维度 | 核心问题 | 对应 7 维 |
|---------|---------|----------|
| ① 可判断 | 能不能判断"有没有问题 / 多严重" | 问题定义 + 诊断分级 |
| ② 可执行 | 步骤是否有明确决策标准 | 步骤+判断 |
| ③ 可迁移 | 是否有案例 + 结构 | 案例 + 核心框架 + 陷阱 + 方法关系 |

> 对应 7 维，可以压缩成：**判断 × 执行 × 迁移**

### 质量分级

| 等级 | 标准 |
|------|------|
| ⭐⭐⭐⭐⭐ S | 7 维全部到位，框架可视化，步骤有判断标准，有完整案例 |
| ⭐⭐⭐⭐ A | 5-6 维到位，可能缺案例或缺诊断分级 |
| ⭐⭐⭐ B | 3-4 维，有框架和步骤，但缺陷阱或方法关系 |
| ⭐⭐ C | 1-2 维，只有定义和简单步骤 |
| ⭐ D | 占位文件，几乎为空 |

## 输出结果

这个 Skill 的输出一定是以下两者之一：
1. **一个"可用方法卡"**——按 7 维协议生成的标准方法卡
2. **一个"方法卡评估报告"**——当前等级 + 缺失维度 + 升级路径

---

## 常见陷阱

1. **"定义充足但判断缺失"**：写了大量"是什么"，但没有"怎么判断是/不是/多严重"
2. **"步骤模糊"**：用"分析一下""考虑XX"作为步骤，缺少具体判断标准
3. **"框架只用文字"**：核心框架是纯文字叙述，没有表格/矩阵/流程图

---

## 方法关系

- **前置**：CG03 认知组装者（先会拆解问题，再设计方法卡）
- **后续**：CG04 创造力的十段评估体系（方法卡设计完成后，评估使用者段位）
- **并行**：所有 Skill（都必须用 CG14 的结构重写）

### CG14 在系统中的位置

CG14 是"母工具"——不是用来做事，而是用来定义怎么做事。

| 角色 | 说明 |
|------|------|
| CG03 → CG14 | 认知组装者用于拆解方法，CG14 把拆解结果结构化为方法卡 |
| CG14 → CG04 | 方法卡设计完成后，CG04 评估使用者在该方法上的段位 |
| CG14 ↔ 所有 Skill | 所有 Skill 都必须经过 CG14 的结构化标准 |

> CG14 做的是"认知工业化"——统一认知表达标准，让方法可以被批量生产、质量可控、系统化调用。
