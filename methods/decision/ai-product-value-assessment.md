# AI产品价值三阶评估法（AI Product Value Assessment）

## Meta
- ID: DC06
- Engine: Decision
- Layer: L4
- Origin: original
- Source: AI产品价值评估Agent
- First Published: InnoLab v3.1

## Definition（一句话定义）

从价值成立度、价值放大度、价值持续度三个维度，用13项指标对需求/产品想法进行系统化打分评估，判断是否值得投入。

## Core Idea（核心思想）

大多数产品失败不是因为"做得不好"，而是因为"不该做"。这个方法的核心是：不问"有没有用"，而问三个更本质的问题——**这是不是真价值？能不能放大？能不能长期存在？** 三层递进，任何一层不成立，都应该停下。

## Use Cases（适用场景）

- 评估一个新的产品需求是否值得做
- 判断一个AI应用/项目设想的商业可行性
- 对多个候选方向进行优先级排序
- 投前/立项前的价值尽调
- 已有项目复盘——当初的评估假设是否成立

## Input（输入）

以下任一：
- 一个需求描述
- 一个产品想法或创意
- 一个AI应用场景
- 一个项目立项提案

## Output（输出）

按五部分输出：
1. 需求简述（1-2句复述）
2. 三维度逐项评估（含判断依据）
3. 打分汇总表
4. 总体结论（一句话核心判断）
5. 风险与改进建议（≤3条）

## Steps（使用步骤）

### 第一阶｜价值成立度（满分20）

判断"这是不是真价值"，4个子项各0-5分：

| 子项 | 核心问题 |
|------|---------|
| 问题真实性 | 是否来自真实场景？不解决是否造成真实损失？ |
| 行为改变度 | 用户是否会因此改变行为？还是只"觉得不错"？ |
| 替代不可逆性 | 一旦使用是否不愿回头？是否形成路径依赖？ |
| 最低价值闭环 | 是否已有最小可运行的价值闭环？不是"等全部做完才有价值"？ |

**红灯规则**：成立度 < 12 → 直接判定为伪需求

### 第二阶｜价值放大度（满分25）

判断"能不能越用越值钱"，5个子项各0-5分：

| 子项 | 核心问题 |
|------|---------|
| 边际成本曲线 | 用户翻倍时成本是否线性增长？是否规模越大越便宜？ |
| 判断可复制性 | 核心判断能否被系统/模型复用？还是强依赖个别专家？ |
| 结构复用率 | 模块/流程能否跨场景复用？还是一次性工程？ |
| 组织替代效应 | 是否减少中间人/中级岗位？是否引发组织结构变化？ |
| 系统护城河 | 数据/流程/反馈是否形成正循环？后来者是否难以复制？ |

**黄灯规则**：放大度 < 15 → 禁止加码（无法规模化）

### 第三阶｜价值持续度（满分20）

判断"能不能长期有效"，4个子项各0-5分：

| 子项 | 核心问题 |
|------|---------|
| 环境敏感度 | 是否强依赖某一技术红利？技术/政策变化是否会立即失效？ |
| 场景迁移能力 | 能否适应新用户/新场景？是否被单一使用方式锁死？ |
| 反馈自进化能力 | 能否通过使用数据自动优化？是否"越用越聪明"？ |
| 认知沉淀价值 | 能否沉淀为组织的长期判断能力？不仅是一次性成果？ |

**判定规则**：
- 持续度 ≥ 14：具备长期价值
- 持续度 < 10：仅适合短期套利

### 综合判定

总分满分 65。用一句话总结：

格式："这是一个【成立/半成立/不成立】的需求，短期价值在于 XXX，长期瓶颈在于 XXX。"

## Example（示例）

输入：「想做一个AI辅助教师备课的工具」

输出概要：
- 成立度 16/20：教师备课确实耗时，痛点真实；但最低价值闭环待验证
- 放大度 18/25：边际成本低（AI生成），可跨学科复用；但护城河偏弱
- 持续度 12/20：依赖当前LLM能力，场景迁移能力较强，自进化待建设
- 结论：半成立需求，短期价值在于解放教师重复劳动，长期瓶颈在于缺乏数据飞轮和护城河

## Pitfalls（注意事项/常见误区）

- 不要为了"显得积极"而给高分——这是筛选工具，不是鼓励工具
- 信息不足时应明确指出"评估前提假设"，而非硬打分
- 成立度红灯（<12）是最严格的门槛——即使放大度和持续度高，伪需求也不值得做
- 三个维度有依赖关系：成立度是基础，放大度是杠杆，持续度是保障

## Deep Understanding（深度理解）

- 与 DC01 场景价值矩阵的区别：场景矩阵是四象限粗筛（快速），三阶评估是13项精细打分（深度）
- 与 ST12 护城河分析的区别：护城河只看壁垒，三阶评估看成立+放大+持续全貌
- 与 PD01 BMC 的区别：BMC 描述"商业模式是什么"，三阶评估判断"这个模式值不值得做"
- 高阶用法：可用来复盘——项目失败后用三阶评估分析"当初哪一阶判断失误"
