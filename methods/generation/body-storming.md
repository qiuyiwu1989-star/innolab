# 行为风暴（Body Storming）

## Meta
- ID: GN09
- Engine: Generation
- Layer: L3
- Origin: classic

---

## Definition
行为风暴是一种通过身体力行地模拟和表演实际使用场景来激发创意的方法。与头脑风暴的"坐而论道"不同，行为风暴要求参与者站起来、走进场景、扮演用户，通过身体感受发现问题和灵感。

## Core Idea
有些问题坐着想不出来，得"演"出来。当你扮演一个老人试图打开一个药瓶、扮演一个抱着孩子的妈妈试图刷卡进门时，身体的感受会告诉你文字描述无法传达的痛点。行为风暴的洞察来自肌肉记忆而非脑力推演。

## Use Cases
- 产品体验优化（发现身体层面的痛点）
- 服务设计中的接触点优化
- 适老化/无障碍设计
- 空间和动线设计
- 团队对用户痛点缺乏同理心时的共情训练

## Input
- 场景描述（用户在什么情境下使用产品/服务）
- 用户角色设定（年龄、身体状况、使用习惯等）
- 可用的道具（产品原型、替代物品、空间环境）
- 参与者（3-6人）

## Output
- 行为风暴记录（每个场景的表演过程和发现）
- 身体层面的痛点清单
- 即兴产生的改进想法
- 需要原型验证的关键发现

## Steps
1. **设场景**：选择1-2个关键使用场景，尽可能还原真实环境（光线、噪音、空间限制等）
2. **分配角色**：参与者轮流扮演用户。尽可能模仿真实用户的身体特征（戴模糊眼镜模拟老花、绑住一只手模拟单手操作等）
3. **模拟任务**：扮演者在场景中完成目标任务，其他人观察并记录。扮演者大声说出每个动作时的感受和想法
4. **暂停与讨论**：每完成一个任务步骤暂停，团队讨论：哪里卡住了？哪里不自然？哪里有意外发现？
5. **即兴改进**：针对发现的痛点，即兴尝试改进方案（换一种操作方式、改一个设计细节）
6. **记录与整理**：记录每个场景的表演过程、关键发现、改进想法
7. **转化为设计**：将身体层面的发现转化为具体的设计改进方向

## Cases
1. **GE医疗的MRI儿童友好设计**：GE团队行为风暴模拟儿童做MRI检查的场景，发现孩子害怕的不是检查本身，而是那个巨大的"太空舱"。团队用纸板搭建了一个"海盗船"主题的MRI外壳，让孩子"扮演海盗冒险"，儿童配合率从30%提升到95%。
2. **IDEO医院药房流程优化**：IDEO团队模拟护士在夜间取药的场景，发现走廊灯光太暗看不清药瓶标签。身体层面的痛点催生了荧光标签设计和走廊地灯指引系统。

## Limitations
- 需要足够的物理空间和道具支持
- 模拟场景与真实场景仍有差距，可能遗漏真实环境中的问题
- 参与者的"表演"质量影响洞察深度
- 对纯数字产品/服务的适用性有限
- 时间成本较高（一个场景可能需要1-2小时）

## Method Relations
- **前置方法**：设计民族志（CG17）——先通过民族志了解真实场景，再用行为风暴模拟关键环节；设计思维（design-thinking）——行为风暴是设计思维"共情"和"测试"阶段的实践方法
- **后续方法**：原型法（GN11）——行为风暴发现的痛点用原型验证改进方案；故事板（GN12）——将行为风暴的发现编成故事板叙事
- **互补方法**：头脑风暴（GN08）——先用行为风暴发现身体层面的痛点，再用头脑风暴产出解决方案
- **对比方法**：与头脑风暴对比——头脑风暴是"想"，行为风暴是"演"。行为风暴的洞察更感性、更具体

## Prompt
你是一位体验设计专家。请对以下产品/服务执行行为风暴分析：

**产品/服务**：[用户填写]
**目标用户**：[用户填写]
**关键场景**：[用户填写]

请模拟执行以下步骤：
1. 设计2个关键使用场景的模拟设置（场景描述、用户角色设定、环境模拟细节）
2. 对每个场景模拟完整的用户任务流程（分步骤描述"扮演者"的动作和感受）
3. 在每个步骤中标注发现的痛点（身体层面、认知层面、情感层面）
4. 提出即兴改进建议
5. 将发现转化为具体的设计方向

要求：
- 用第一人称描述扮演者的感受（"我感到..."、"我试图..."）
- 细节要具体（"手指够不到按钮"而不是"操作不便"）
- 关注身体层面的体验，而不只是功能逻辑

输出格式请严格按照Output Format要求。
