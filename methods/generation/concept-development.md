# 概念提炼（Concept Development）

## Meta
- ID: GN10
- Engine: Generation
- Layer: L3
- Origin: classic

---

## Definition
概念提炼是将大量零散的创意想法通过分类、浓缩和结构化，转化为可执行的产品/服务概念的过程。它是创意发散阶段和原型制作阶段之间的关键桥梁，确保团队从"很多想法"过渡到"几个好概念"。

## Core Idea
创意是一堆散珠子，概念是串起来的项链。概念提炼的本质工作是两件事：分类（把相似创意归堆）和浓缩（每堆提炼一个核心主张）。一个好概念应该能在30秒内说清楚"它是什么、给谁、解决什么问题、凭什么不一样"。

## Use Cases
- 头脑风暴/行为风暴之后收敛创意
- 将用户研究洞见转化为产品方向
- 产品立项前的概念定义
- 创业方向从发散到聚焦
- 跨部门对齐产品愿景

## Input
- 创意列表（来自头脑风暴、What If、行为风暴等发散方法）
- 用户洞见或需求描述
- 约束条件（技术能力、资源限制、时间窗口）
- 战略方向指引（可选）

## Output
- 概念卡片（每个概念一张，包含核心主张、目标用户、关键价值、差异化点）
- 概念对比矩阵
- 推荐概念及理由

## Steps
1. **创意归堆**：将所有创意按主题/方向分为3-6个创意群组
2. **群组命名**：为每个群组起一个能激发想象的名称（不是描述性的，而是方向性的）
3. **概念萃取**：从每个群组中萃取核心思想，用一句话表述："我们为[目标用户]提供[什么]，帮助他们[解决什么问题]，与[竞品/现状]不同的是[差异化点]"
4. **概念深化**：为每个概念补充：关键功能（3个）、用户场景（1个）、成功指标（1个）
5. **概念评估**：从用户价值、技术可行性、商业潜力、差异化四个维度评估每个概念
6. **概念组合**：检查概念之间是否有组合可能——两个概念合并是否更强？
7. **最终推荐**：选出1-2个推荐概念进入原型阶段

## Cases
1. **Slack的概念提炼**：Stewart Butterfield的团队原本在做游戏，但发现内部沟通工具本身是更好的产品。概念提炼过程：将"游戏内聊天""文件分享""消息搜索"等创意归为"团队沟通"群组，萃取核心主张——"为团队提供比邮件更轻、比即时通讯更有组织性的沟通工具"。
2. **Dyson吸尘器概念**：James Dyson做了5127个原型，概念提炼的关键步骤是将所有"气旋分离"相关创意浓缩为一个概念："不需要集尘袋的吸尘器，吸力永不衰减"——一句话定义了整个品类。

## Limitations
- 归堆和萃取依赖主持人的经验，可能遗漏跨群组的组合机会
- 概念卡片的"一句话主张"可能过度简化，丢失创意的丰富性
- 评估维度的权重因团队而异，结果可能偏向某些偏好
- 过早收敛的风险——可能淘汰了当前看起来不成熟但有长期潜力的想法

## Method Relations
- **前置方法**：头脑风暴（GN08）——概念提炼的主要输入来源；What If（GN07）——颠覆性创意的概念化
- **后续方法**：原型法（GN11）——概念提炼选出的概念进入原型验证；评估矩阵（DC07）——对概念做更系统的多标准评估
- **互补方法**：金字塔原理——概念的一句话主张应符合金字塔结构（结论先行）
- **对比方法**：与亲和图对比——亲和图是无预设的分类发现模式，概念提炼是有目的的收敛转化

## Prompt
你是一位产品概念专家。请对以下创意集合执行概念提炼：

**项目名称**：[用户填写]
**创意来源**：[用户粘贴的创意列表]
**约束条件**：[用户填写]
**战略方向**：[用户填写，可选]

请按以下步骤执行：
1. 将创意按主题归为3-6个群组
2. 为每个群组萃取一个产品概念（用标准主张格式）
3. 为每个概念补充关键功能、用户场景、成功指标
4. 从用户价值/可行性/商业潜力/差异化四个维度评估
5. 做概念对比矩阵
6. 给出推荐概念和下一步建议

要求：
- 概念主张要在30秒内能说清楚
- 评估要客观，不要因为某个概念"酷"就打高分
- 检查概念之间是否有组合可能

输出格式请严格按照Output Format要求。
