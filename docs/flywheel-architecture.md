# 系统设计：数据飞轮 →「越用越聪明」

> 状态：设计已定 / Phase 1 进行中 · 日期 2026-06

## 0. 前提（决定整个架构）

不掌握 MiMo 训练，所以「越用越聪明」**不靠微调模型**，只能沉淀在模型外的三层：
上下文层（每次注入什么）、检索/路由层（面对新问题 retrieve 什么）、内容层（方法/案例随用增长）。
本质是 **RAG 式上下文飞轮**：数据越多 → 能 retrieve 到的好东西越多 → 注入越准 → 输出越好。

## 1. 四个飞轮圈 · 现状

| 圈 | 已有 | 状态 |
|---|---|---|
| ① 个性化记忆 | `getMemoryForUser` 注入最近判断 | ✅ 基础闭环（Phase 1 增强中） |
| ② 群体智慧 | `methodUsageStats`/`conversationInsights` | 仅观察，未回流 |
| ③ 案例自增长 | `markCandidateByTs` 人工标候选 | 半手动 |
| ④ 质量纠偏 | `feedback` 表 + 看板 | 仅观察，未回流 |

诊断：目前只有 ① 真正影响输出，②③④ 停在「收集+看板」。

## 2. 目标架构：用户与 MiMo 之间加「检索/上下文层」

```
用户问题 + userKey
  → 检索层：① 本人记忆  ② 最相似的过去高分推演(pgvector)  ③ 最相关案例(pgvector)  ④ 质量信号(踩的排除/赞的加权)
  → 组装上下文 → MiMo 推演(TP) [需要实时事实→官方 sk- 联网搜索]
  → 输出 → 落库 + 生成 embedding → 👍/👎 反馈回流到 ④ 调整检索排序
```

## 3. 各圈设计

- **① 记忆**：从「最近 2 次判断」升级为沉淀式用户档案（关注领域 / 反复纠结的核心问题 / 公司背景 / 历史结论）。回头用户接上脉络，不从零问。
- **② 群体智慧（核心跃迁，需 pgvector）**：新问题 → 向量检索「最相似且被赞过的历史推演」做 few-shot 注入。每多一个好推演，对相似问题就更强。
- **③ 案例自增长**：自动标高质量推演为候选 → 人工审核 → 升级进案例库注入（人留在环里，守住案例真实性）。
- **④ 质量纠偏**：👎+吐槽聚类成失败模式 → 改提示词/补缺失方法（`unknownIds` 已暴露缺口）；被踩答案在 ② 检索里降权。

## 4. 关键依赖 & 取舍

- **pgvector embedding** 是 ②③ 命门；Supabase 云已支持，加 `embedding vector(N)` 列即可；需一个 embedding 接口。
- **隐私**：注入他人历史推演须脱敏（只存 ip_hash；范例只取 prompt+output，不带联系方式）；案例走人工审核。
- **冷启动 = 真瓶颈**：飞轮燃料是用量，现仅 ~13 条对话。② 语义检索在小数据量几乎无收益——**重型检索系统不该现在建**（为没有的数据造引擎）。

## 5. 分阶段（别一上来造重器）

- **Phase 1（现在，低成本）**：① 沉淀式记忆增强；③ 自动标候选；④ 看板 👎 聚类 + 暴露缺失方法。无需 embedding。
- **Phase 2（用量 > 几百条再做）**：上 pgvector，②③ 语义检索注入——真正的跃迁。
- **Phase 3**：质量加权检索（④ 反哺 ②）、半自动案例晋升。

**核心取舍**：理性顺序 = Phase 1 廉价闭环 + **全力分发引流**（用量是燃料），Phase 2 推迟到有数据。先造引擎后没油是此类产品最常见的坑。
